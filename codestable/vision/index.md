# Vision：可核查的多科目考试工作台

## 产品核心

ExamTwin 帮助教师和内容维护者把考试局资料变成可核查、可复用的知识与作答工作流：
用户能选择科目，提交整卷试题或学生答案，看到逐题答案、知识点、原文引用和待复核建议分，
并能回到产生结论的官方资料。模型负责提取、检索和提出建议，不替代教师判断。

## 用户旅程

- **维护证据基础**：选择 SubjectPack，清点和转换课纲、真题、评分标准与报告，发布可恢复的知识图谱和检索索引。
- **整卷证据作答**：上传试卷，观察持久任务进度，逐题查看原卷视觉观察、答案、计算/图表产物和引用；单题失败可重试。
- **评分与复核**：提交学生 Markdown 答案，只在严格配对 Mark Scheme 存在时获得逐 rubric 建议，最终由教师确认或改分。
- **核查知识与难度**：从知识点回到课纲或表现证据，清楚区分官方量化、官方定性、历史估计和 AI 冷启动。

## 能力版图

- **科目运行时**：SubjectPack 声明科目边界、Unit、资料目录、索引和允许的答题能力。
- **证据生产**：资料清点、MinerU 转换、对象存储、知识候选、质量门禁和原子发布。
- **检索与 Agent**：科目隔离的混合召回、rerank、原文读取、受控计算/绘图工具和可审计 Agent run。
- **整卷任务**：PostgreSQL 持久队列、租约、检查点、事件流、逐题结果和可恢复 Worker。
- **评分治理**：严格配对、rubric 原子、建议分、人工复核和不可冒充正式成绩的状态边界。
- **工作台**：按科目展示资料、知识、作答、评分和复核，不在前端复制学科规则。

## 基础与边界

- syllabus 决定知识边界；Question Paper、Mark Scheme 和 Examiner Report 保留稳定来源身份。
- 每个结论应能回到来源页、原文或明确的算法/模型版本；证据不足时允许拒答。
- 付费模型只在显式任务中调用；构建失败保留上一正式图谱或索引版本。
- 当前按本机受信单用户工作台设计，只绑定 loopback；没有账号、租户和公网授权模型。
- 自动评分永远进入 `pending_review`，不直接发布成绩。
- “ExamTwin”是产品方向，不表示已经存在学生数字孪生、认知状态机或长期学习画像。

## 统一语言

- **证据型**：输出携带可读取来源，不等于模型断言“grounded”。
- **严格配对**：同科目、年份、考季和 Unit 的 Question Paper / Mark Scheme 配对。
- **建议分**：等待教师复核的模型输出，不是成绩。
- **难度观测**：带来源和方法的一条事实或估计；聚合难度不是不可追溯的单值标签。
- **SubjectPack**：版本化学科运行契约，不是任意可执行插件。
