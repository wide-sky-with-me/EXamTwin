# 整卷视觉与模型调用延迟优化

## 目标

在不降低逐页视觉门禁、证据引用、分题完整性和最终答案契约的前提下，减少整卷处理中的无效模型重试与重复终稿调用，并让视觉请求使用模型原生结构化输出和已声明的推理强度。

## 范围

- 包含：逐页 `PaperVisionReviewer` 请求契约；ReAct 已产出合法终稿时的本地验收；相关可观测日志、测试和真实供应商冒烟。
- 不包含：合并多页视觉请求、跳过页面复核、降低渲染清晰度、改模型、取消知识检索或放宽引用/子题覆盖门禁。

## 归属

- 独立 issue。
- 来源 Vision：`codestable/vision/index.md` 的整卷证据作答旅程。
- 相关 spec：`codestable/spec/index.md` 的整卷视觉、模型作答和可靠性边界。

## 背景与证据

- 当前视觉复核保持每物理页一请求：Worker 并发 chunk，但 `review_chunk` 在每个 chunk 内串行拆成单页请求。这个质量边界正确；请求却只靠提示词约束 JSON，且 `PAPER_VISION_REASONING_EFFORT` 没有进入 `gpt-5.6` 请求。
- 当前 ReAct 主模型即使已经输出通过 `AgentFinalPayload` 解析的 JSON，仍固定再调用一次结构化终稿模型；本地已经具备子题覆盖、引用编号和公开内容校验，重复调用不是正确性前提。
- 2026-08-17 对现有 PostgreSQL 运行记录的只读基线：最近数学/经济任务解析只需约 17–20 秒；视觉与分题阶段数学 332.2 秒、经济 1598.1 秒；答题窗口分别为 614.3 秒和 1303.6 秒。相同固定卷的视觉与分题阶段历史波动约 267.5–2072.7 秒，说明外部模型请求及竞争是主要尾延迟来源。
- 最新两份任务单题平均 89.9–108.5 秒；30 道题共执行 36 次 `knowledge_search`，已有终稿模型调用位于每题主路径，因此消除已满足契约时的重复终稿调用可直接减少请求数，而不靠提高并发掩盖延迟。

## 现状如何工作

PDF 按页经 MinerU 转换后，Worker 以有界 chunk 并发调度视觉复核，而每个 chunk 内仍逐页串行调用视觉模型并做页码、图片保留、页面语义和置信度门禁；分题后每题进入 ReAct，必须检索证据并按题使用视觉/计算/绘图工具，主模型返回终稿后又固定交给结构化终稿模型重写并再次本地验证。

## 影响范围

- 必须修改：`paper_vision.py` 的供应商请求参数；`react_runner.py` 的终稿决策。
- 需要验证：逐页隔离、图片回退、低置信度/HTTP 重试、子题标签、引用编号、隐私推理过滤、终稿 provider 降级。
- 仍待调查：供应商在双卷并发下的全局吞吐上限；本 issue 不用未经实测的更高并发替代调用削减。

## 质量目标

- 功能适宜性：每页仍独立复核，所有物理页、问题内容、来源图片和分类记录继续通过现有门禁。
- 性能效率：已合法的主模型终稿不再产生第二次模型调用；视觉响应由 JSON Schema 约束，减少格式性重试。
- 可靠性：主模型终稿只有通过与结构化终稿相同的本地子题与引用校验才走快路径；失败立即回到现有终稿 provider。
- 可观测性：记录终稿本地验收事件，真实冒烟记录请求参数和调用次数。

## 方案判断

- 保留一页一请求。多页合并会重新引入跨页视觉归属风险，不能用质量换请求数。
- 不提高视觉并发。当前尾延迟高度波动，先减少请求并提高一次成功率；并发上限需要独立的双卷供应商基准。
- 明确接线供应商协议：视觉请求使用严格 JSON Schema；`gpt-5.6` 使用配置的 `reasoning_effort`，其他模型继续使用确定性参数。配置接线及请求体必须由测试和真实调用覆盖。
- ReAct 终稿先按 `AgentFinalPayload`、精确子题标签和允许引用集合本地验收；验收失败才调用结构化终稿 provider。

## 验证

- 自动回归：`uv run pytest backend/tests/test_paper_vision.py backend/tests/test_react_runner.py backend/tests/test_structured_finalization.py -q`，79 项通过。
- 静态检查：变更生产模块 `basedpyright` 为 0 error；变更文件 Ruff check 与 format check 全部通过。
- 真实视觉供应商冒烟：单页可见代数题经当前 `gpt-5.6` 端点一次返回 strict JSON Schema 响应，页码、`question` 分类、题面和置信度均通过现有门禁，置信度为 1.0。
- 真实回答供应商冒烟：使用一条受控 syllabus 证据运行完整 ReAct 主路径，模型返回正文引用 `[S1]` 与 `citation_ids=["S1"]` 一致的 `AgentFinalPayload`；本地引用/子题门禁通过，终稿 provider 调用数为 0，结果保持 `grounded=true`。
- 反例回归覆盖正文 `[S1]` 但声明空引用、正文与声明引用反向不一致、伪造引用、终稿 provider 超时以及合法结构化终稿；不一致候选必须进入 provider，不能借兼容修复进入快路径。

## 执行记录

- 2026-08-17：保留一页一请求、当前渲染和全部视觉门禁；视觉请求接入 strict JSON Schema，并把配置的 `reasoning_effort` 传给 `gpt-5.6`，其他模型继续使用确定性参数。
- 2026-08-17：ReAct 终稿解析保留模型原始引用声明；工作流统一物化并验收主模型与 provider 的 `AgentFinalPayload`，精确检查子题结构、正文引用与声明顺序及允许引用集合。provider 只生成和解析结构化载荷，运行时不再重复校验或补写空引用；两类候选均不合法时失败关闭。
- 2026-08-17：完成自动回归和两条真实供应商冒烟；合法结构化答案实测省去一次终稿模型调用。
