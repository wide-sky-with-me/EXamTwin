# 加固拆题去重与来源页协调

## 做了什么

修复整卷拆题时视觉主稿与 PDF 文本恢复附录使用 `01`/`1`、`17`/`17.1` 等题号变体而产生重复顶层题的问题。来源页严格校验保持不放宽，重复题在进入校验前按顶层题身份合并。

进一步增加受约束的模型修复慢路径：只有确定性来源页协调失败时，结构化模型才对候选题做顶层分组与物理顺序恢复。模型只返回候选索引分组；本地代码要求每个候选恰好使用一次、题号来自组内候选、顶层题号不重复，并再次执行物理页标记校验。模型不能写入或覆盖 `source_pages`。

## 改了哪些

- `backend/src/examtwin/services/paper_parsing.py` — 为来源页无法协调增加专用失败类型，使模型修复只响应这一种窄失败。
- `backend/src/examtwin/services/paper_answering.py` — 规范化顶层题号；在已有完整顶层题时丢弃恢复附录拆出的子题碎片；确定性协调失败后调用结构化模型恢复候选分组与顺序，并在本地验证、合并和重算来源页。
- `backend/tests/test_paper_answering.py` — 覆盖前导零、点号子题、正常路径不调用模型、乱序候选由模型恢复，以及模型遗漏候选时必须拒绝。

## 怎么验证的

回归测试先稳定复现原 ValueError，修复后通过。纸卷作答与 Worker 相关测试 `23 passed`，Ruff、basedpyright 和修改模块 LSP diagnostics 均通过。真实失败任务 `9c05863a-483a-4ce7-841d-e78ce4b0e277` 复用原检查点重试后识别 21 道顶层题并进入 `answering`，原来源页异常消失。另以真实 `paper_split_model` 执行乱序候选 smoke test，模型返回分组经本地校验后得到题序 `1, 2, 3` 和来源页 `[1], [2], [3]`。共享 Python 镜像已重建，两个 `paper-worker` 容器已替换并保持运行。
