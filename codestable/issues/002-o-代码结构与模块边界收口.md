# 代码结构与模块边界收口

## 目标

在不改变现有整卷作答、RAG、评分、知识构建和前端交互契约的前提下，让数据访问、
学科适配、长任务编排、Agent 循环、API 和前端页面各自有单一责任边界；测试围绕可观察
行为和独立风险，不继续复制内部实现。

## 范围

- 包含：Alembic/ORM 单一数据边界，移除旧 `Database` SQL 兼容层；学科上下文与课纲
  正规化策略隔离；过大后端模块按业务生命周期拆分；API 仅保留协议转换；前端页面
  与证据组件分层；删除重复或仅锁定实现细节的测试。
- 不包含：改变模型供应商、重新生成付费难度数据、全量 MinerU/Qdrant 重建、
  改变学生答案评分权威边界。

## 归属

- 独立 issue；与知识生产 Epic 和整卷作答 Issue 有交叉，但不替代它们的产品验收。
- 相关 spec：`codestable/spec/index.md`、
  `codestable/epics/001-o-多科目知识生产与难度证据流水线/spec.md`、
  `codestable/issues/001-o-整卷证据作答与细粒度知识图谱.md`。

## 已处理问题与剩余观察

- 数据访问已统一为 Alembic、SQLAlchemy Session 和领域 Repository；服务/API/测试不再传递
  `Database` 兼容对象，业务服务无拼接 SQL。
- 学科规则已移动到 `subjects/<subject>.py`；通用课纲提取器只调用 SubjectPack 自带的文字
  正规化策略，不再注册 Integration、连续随机变量或 Newton 定律等数学术语。
- 整卷任务已拆成 API 用例 `PaperJobService`、Worker 检查点边界 `PaperJobRuntime`、
  `PaperSourceStore` 与 `SafeLocalStorage`；Worker 不再读取服务的 `root` 或调用私有文件函数。
- `api/router.py` 只组合能力路由；生产代码按 common/evidence/grading/knowledge/papers 直接导入
  schema，不再通过全量聚合模块产生无关依赖。
- 删除了只断言 Factory 内部对象身份的重复测试；PostgreSQL 集成测试改为每次创建并只清理
  自有临时数据库。仍保留较大的测试文件，因为现存用例覆盖的供应商故障、租约、重试、视觉
  产物和协议恢复是不同失败风险，不按文件长度机械删除。
- 剩余观察：`paper_worker.py` 仍集中表达同一 Worker 的 parse/split/answer 三阶段；当前拆分后
  每阶段通过窄 Runtime/Store 边界持久化，尚无重复变化轴证明继续拆类会降低复杂度。
- 答题 Agent 的公共消息、模型、协议、工具调用治理和结构化输出已经收入 provider-neutral
  `agent_harness`；LlamaIndex ReAct 与 LiteLLM 分别留在 answering/service adapter。评分和
  课纲难度共用结构化任务原语，静态平台政策由包内模板加载，动态数据分消息注入。当前剩余
  工作是完整门禁和运行态穿刺，不再继续为了抽象完整性拆分小类。

## 行为保持

- 必须保持的外部行为：现有 REST/WebSocket 路径和 JSON 形状，已持久任务/答案/证据可读，
  单卷租约、逐题重试、图形产物门禁、Mark Scheme 唯一评分权威不变。
- 兼容性边界：已有 PostgreSQL 从当前 Alembic revision 平滑升级；全新空库仅靠
  `alembic upgrade head` 得到完整 schema；不删除现有业务数据。
- 不借重构顺手改变的行为：难度算法、检索排名、答案模型选择、并发上限和前端视觉风格。
- Agent Harness 重切必须保持：强制知识检索、引用闭合、必需作图产物、严格配卷
  Mark Scheme、人工复核、有界工具调用与不持久化隐式思维链。

## 现状如何工作

FastAPI/CLI 构建旧 `Database` 对象，多数服务立即用其 URL 再构建 SQLAlchemy
Repository；少数工具通过 `isinstance(Database)` 在真实存储与测试替身之间分支。API 、
Worker 和 Agent Factory 因此同时理解配置、存储细节和领域服务构造。

## 影响范围

- 必须修改：`persistence/`、服务构造器、API 组合根、CLI/Worker 入口、学科注册、后端
  大模块、相关测试组织。
- 需要验证：空库迁移、已有库升级、普通/集成测试、Ruff、前端 lint/type/build、Compose
  配置与运行服务健康。
- 仍待调查：模块拆分后 Codegraph 影响面是否真实收窄；需在同一份测试集合和运行路径上对比。

## 质量目标

- 可维护性 / 模块化、可分析性、可测试性：
  - 目标：每个业务生命周期有单一所有者；调用方通过 Repository/Port 而非 SQL/URL/类型分支使用
    能力；模块拆分后测试从可观察接口进入。
  - 来源：用户决定与本次审计。
  - 预期证据：Codegraph 依赖面、无服务层 SQL 扫描、窄测试与静态检查。
- 可靠性 / 可恢复性：
  - 目标：重构不改变租约、检查点、条件提交和原子发布语义；失败不破坏已发布图谱/索引。
  - 来源：Project/Epic Spec。
  - 预期证据：PostgreSQL 租约与迁移集成测试、Qdrant 发布契约测试。
- 兼容性 / 互操作性：
  - 目标：前端与现有 API 不需同步改变对外合约；新科目选择不穿越另一科的资料、知识点和
    向量 alias。
  - 来源：知识生产 Epic 与本次风险扫描。
  - 预期证据：9660/9640 科目隔离测试、API 契约测试。

## 方案判断

- 以 SQLAlchemy `sessionmaker` 与明确 Repository/Protocol 作为数据边界，不新建包含所有库的
  Service Locator；组合根一次构建真实依赖。
- 按业务变化轴拆分大模块，不按固定行数分片；只转发的包装层不保留。
- 学科专用课纲正规化放入已注册学科模块；通用提取器只处理结构，不认识数学术语。
- 测试只保留一份能拦住独立风险的证据；重复的 helper/相邻内部分支断言被合并或删除。
- 不复制 Pi 的通用开发者 Agent，而是在 EXamTwin 内部建立有两个真实调用方的 Harness。
  Harness 只拥有消息/模型 port、工具执行与调用治理、结构化输出、预算/停止和执行
  记录；考试答题、评分和难度的规则由 Profile/Policy 组合。
- 不实现生产自修改、未评审可执行插件或隐式思维树。Subject Package 仍只能选择
  服务端白名单能力；可恢复性用公开消息、工具结果、checkpoint 和 retry lineage 表达。

## 实现设计

### 一步步怎么改

1. 固化 Alembic 为唯一 schema 来源，把已有领域持久化收入 ORM/Repository。
2. 移除 `Database` 兼容层，API/CLI/Worker 从组合根注入 Repository 或 Port。
3. 把学科正规化策略移出通用课纲提取器，让检索、索引和任务全程使用非空
   `SubjectContext`。
4. 按生命周期拆分知识投影/匹配、转换/索引、任务服务/Worker 阶段和 Agent 协议/运行时。
5. 拆分 API/schema 和最大的测试文件，删除重复或仅锁内部细节的测试。
6. 运行空库/已有库迁移、全量后端/前端门禁和 Compose 健康穿刺，然后回写实际执行记录。
7. 把 Agent 公共消息、模型调用、工具调用与结构化输出契约收入不依赖 LlamaIndex
   的 `agent_harness`；LlamaIndex 只作为现有模型/工具的 adapter。
8. 从 ReAct runner 抽出协议 adapter 和 ToolRunController/ToolExecutor，把必选工具、引用、
   产物和 Mark Scheme 权威留在领域 Policy，不降低约束。
9. 让评分和课纲难度复用同一结构化模型调用原语；评分仍强制 pending review，
   难度仍保留现有证据等级和算法。
10. 用 QuestionSpec 和 Profile 在每题开始前缩小工具面；当可观察证据证明工具数量/
    schema 已成为成本瓶颈时，再升级为 Tool Search，本轮不引入第二个 Agent router。

### 怎么确认做对

- `rg` 确认服务/API 无 SQL，旧 `Database` 类与 `isinstance(Database)` 分支消失。
- 9660/9640 共用提取器，数学专用文本策略不在通用模块；两科隔离断言通过。
- 空库只跑 Alembic 得到完整表/索引/触发器；现有库无损升级。
- 后端普通/集成测试、Ruff、前端 Vitest/ESLint/TypeScript/Vite 和 Compose 服务健康通过。
