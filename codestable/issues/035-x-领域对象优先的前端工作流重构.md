# 领域对象优先的前端工作流重构

## 目标

把当前并列的“科目管理、试卷管理、试卷作答、答案评分、复核队列”重切为领域对象优先的信息架构：科目与试卷保存事实，任务承载作答与评分运行，复核完成最终人工决策。用户从试卷详情连续进入作答、评分和复核，不再在每个页面重复选择科目、试卷和材料；页面上下文由 URL 和后端事实决定。

同时用 Ant Design 6 替换项目自研的通用控件，用 TanStack Query 统一服务端状态、请求取消和精确失效；保留 EXamTwin 独有的试卷证据、评分细目、Markdown/KaTeX 和响应式领域布局。

## 范围

- 包含：导航、路由、科目详情、试卷详情、作答任务、评分任务、复核工作台、请求上下文、服务端状态所有权、Ant Design 组件迁移和旧 CSS 清理。
- 不包含：修改考试身份与严格配对规则、评分算法、Rubric/assessment 权威边界、后台 Worker、数据库模型、OCR、重新构建既有知识库或重跑历史任务。

## 当前问题

- `frontend/src/App.tsx` 把科目、试卷、作答、评分和复核作为五个并列入口；这五项实际是“资源准备 → 运行 → 人工决策”的同一生命周期，不是同层级对象。
- 科目资料和知识库被塞进 1080px 管理弹窗，不能稳定复制、刷新或前进后退；上传、构建和删除共享一个 `busy/error` 状态。
- 试卷详情通过 `PaperManagement` 的七个导航回调拼接流程；同一业务对象在列表、详情、作答和评分页面被重复发现和选择。
- 作答页面把活动任务 ID 放入 `localStorage`；`/answering` 本身不能唯一说明用户正在看的任务，URL 与页面事实可能分叉。
- 评分页面同时拥有科目、作答记录、Mark Scheme、Rubric、assessment、overview、步骤和十余个请求版本/ref；`step` 可以与后端事实不一致，组件需要手工阻止晚返回覆盖当前选择。
- 复核卡片只显示题号、分数、置信度和评分原子数量，用户看不到题目、答案、逐原子得分和证据就能确认或改分，不满足可审计人工决策所需上下文。
- 六个主要页面/工作区共 3758 行；其中 `PaperAnswering.tsx` 878 行、`Grading.tsx` 1380 行。页面组件同时承担路由、远程状态、流程判断、表单、长任务订阅和渲染。

## 行为保持

- 必须保持：科目隔离、试卷单元与资料显式关联、严格 `pair_key`、持久 Worker、断点重试、逐题答案与来源、官方/AI 评分标准门禁、人工确认和改分审计。
- 兼容性边界：现有深链接和持久数据可读；旧页面 URL 只做一次声明式重定向到新 canonical URL，不保留两套页面实现。
- 不借重构改变：模型调用与评分计算。用户已明确确认作答删除为永久删除；删除作答时必须同步清除其关联评分、复核审计并让对应作答对象进入立即回收，不得只断开关联留下孤儿记录或文件。

## UI 变化 / 实际与预期

- 用户选择：领域对象优先。
- 主导航目标：

```text
ExamTwin
├─ 科目
├─ 试卷库
│  └─ 试卷详情 Modal
│     ├─ 作答记录 Modal（AI 作答 / 外部答卷）
│     ├─ 作答详情 Modal
│     └─ 指定作答的评分 Modal
└─ 复核
```

- 业务生命周期：

```mermaid
flowchart LR
  S[科目与资料] --> P[试卷单元与严格配对材料]
  P --> A[作答任务]
  A --> G[评分任务]
  G --> R[人工复核]
  R --> F[最终评分]
```

- 稳定路由：

```text
/subjects
/subjects/:subjectId
/subjects/:subjectId/materials
/subjects/:subjectId/knowledge

/papers
/subjects/:subjectId/papers
/subjects/:subjectId/papers/:paperUnitId
/subjects/:subjectId/papers/:paperUnitId/answers
/subjects/:subjectId/papers/:paperUnitId/jobs/:jobId/answering
/subjects/:subjectId/papers/:paperUnitId/jobs/:jobId/grading

/reviews
/reviews/:assessmentId
```

- `/papers` 和 `/reviews` 是领域索引；试卷详情、作答记录、作答详情和评分始终使用带 `subjectId`、`paperUnitId`、必要时 `jobId` 的 canonical URL。
- 科目管理使用稳定页面；试卷相关详情由 URL 驱动 Modal，关闭、返回、刷新和浏览器前进后退都回到真实试卷上文。
- 弹窗标题表达真实上文，例如“试卷评分 · 2025 June P2”。

## 页面责任与动作契约

### 科目

- `/subjects`：搜索、筛选、新建和进入科目；不直接承载资料上传或知识库构建。
- `/subjects/:subjectId`：基本事实和能力状态；资料、知识版本使用子路由。
- `/materials`：资料列表是主内容，上传为 Drawer；转换状态就近更新，删除只影响当前资料。
- `/knowledge`：只展示核心/补充库输入、版本、发布状态与构建动作；构建任务不阻塞其他资料操作。

### 试卷库

- `/papers`：跨科目搜索入口；科目是筛选条件，不是进入列表前必须点击的卡片门禁。
- 试卷详情是 Question Paper、Mark Scheme、Source Booklet、作答任务和评分任务的唯一共同上文。
- “新建作答”从当前试卷和具体 Question Paper 创建任务，不再重复选择科目和试卷。
- “开始评分”必须选择当前试卷下一个已完成作答任务；严格配对的 Mark Scheme 自动成为候选，多个候选时显式选择。

### 试卷内作答记录

- `/:paperUnitId/answers` 只管理当前试卷的作答记录，不再提供跨科目平级作答队列。
- 任务详情由 URL 中的 `jobId` 唯一确定；活动任务不得依赖 `localStorage` 恢复。`localStorage` 只保留主题、复核人和用户级显示偏好。
- SSE 更新任务 query cache；刷新、复制 URL、浏览器前进后退均得到同一任务。
- 失败、部分失败、完成分别由后端状态驱动；重试后保留旧尝试审计，不把页面步骤重置成新任务。

### 试卷内评分

- 评分上下文必须包含一个明确的 `jobId`，不再从 `paperUnitId` 下隐式选择第一条作答记录。
- 页面阶段由事实派生，不保存独立可漂移的 `step`：

```text
materials_missing
→ rubric_preparing
→ rubric_review
→ ready_to_grade
→ grading
→ graded
→ awaiting_review / finalized
```

- `rubric.status`、assessment 完成度和复核状态决定阶段；页面只保存当前展开题号、Drawer 开关等瞬时状态。
- Rubric 审核是独立子工作区/Drawer；确认前不能评分，确认后回到同一任务上下文。
- 逐题评分和整卷结果共享同一任务 URL；题号可放入 query/hash，刷新不丢当前题。

### 复核

- `/reviews` 提供跨科目队列、科目/置信度筛选和复核人身份。
- `/reviews/:assessmentId` 或桌面分栏详情必须展示题目、答案、Rubric 原子、每项得分、证据/警告、建议总分和置信度。
- “确认建议分”和“改分并确认”保持现有权威边界；改分必须填写有效范围内的最终分。决定成功后自动进入下一条，失败时保留当前上下文。

## 状态所有权

| 状态 | 唯一所有者 | 禁止做法 |
|---|---|---|
| 科目、试卷、任务、Rubric、assessment、复核项 | TanStack Query cache | 在页面复制一份长期 `useState` |
| subjectId、paperUnitId、jobId、assessmentId、筛选、页码 | URL | 放入全局 mutable singleton 或活动任务 localStorage |
| 表单草稿与校验 | Ant Design Form | 每个字段一组散落状态 |
| SSE 任务快照 | 对应 job query | 再维护第二份 `job` 状态 |
| Modal/Drawer、展开题号、hover | 局部组件 | 上升到 App 全局状态 |
| 请求科目上下文 | 每次请求显式参数/路由 scope | 页面调用 `setApiSubject` 改写全局请求头 |

- Query key 必须包含科目和业务身份，例如 `['paper', subjectId, paperUnitId]`、`['answer-job', subjectId, jobId]`。
- 查询函数消费 `AbortSignal`；路由切换自动取消旧请求，不再使用十组 request revision ref 模拟取消。
- Mutation 成功后只失效相关 key；SSE 使用 `setQueryData` 更新活动任务，不全量刷新整个应用。
- 不引入 XState：评分阶段可由已有后端事实纯函数派生，额外状态机运行时会产生第二事实源。

## 组件与视觉设计

- `antd@6` 负责 Layout、Menu、Breadcrumb、Form、Table/List、Input、Select、Upload、Modal、Drawer、Pagination、Tabs、Steps、Alert、Tag、Badge、Empty、Skeleton、message/notification。
- 根节点使用 `ConfigProvider + App + zhCN`；保留当前蓝色、冷灰表面、系统字体、浅/深/跟随系统主题。
- 暂不引入 ProComponents；只有三个以上稳定同构 CRUD 页面出现后再评估。
- Lucide、React Router、OpenAPI client、React Markdown 和 KaTeX 保留。
- 自定义 CSS 只用于页面空间关系、试卷/证据/评分领域内容和移动端信息重排，不覆盖 `.ant-*` 内部 DOM。

## 响应式模式

- ≥1024px：固定侧栏；列表/详情可双栏，复核使用队列 + 证据详情分栏。
- 600–1023px：可折叠侧栏；详情单栏，辅助信息进入 Drawer。
- <600px：底部主导航只显示“科目、试卷、复核”三项；作答与评分从所属试卷的弹窗链路进入。详情是整页，禁止在窄屏内嵌桌面 Table。
- 搜索、筛选和主要操作在所有尺寸下保持同一语义；移动端只改变布局，不删减证据和危险操作说明。
- 试卷、任务和复核列表在窄屏使用领域卡片；不能靠水平滚动暴露关键列。

## 方案判断

选择“领域对象优先”，不保留五个平级入口。原因：科目和试卷是持久业务对象，作答和评分是对试卷产生的运行，复核是对评分结果的人工决策。平级导航会迫使页面重复发现上文；对象详情作为共同上文可以同时降低点击、状态数量和错误配对风险。

增加 TanStack Query 是有界新增：当前 `Grading` 依赖多个请求序号、ref 和重复远程状态，已经满足“重复且容易晚返回覆盖”的引入条件。它只拥有服务端状态，不接管 URL、表单或领域阶段。

## 风险与穿刺

1. 先打通一条真实纵向路径：`试卷详情 → 创建作答 → 作答详情 → 评分详情 → 复核详情`，用 9660 真实数据证明 URL、请求科目和证据不丢失。
2. 最大技术风险是现有全局 `setApiSubject`；先把新路径改为请求显式科目，旧页面在迁移期间只读，避免两个入口同时写全局头。
3. 最大交互风险是移动端详情过密；纵向穿刺必须同时验证 1440px 与 390px，不在最后统一压缩。
4. 最大回归风险是旧路由与 localStorage 自动恢复；建立 canonical URL 重定向测试后一次性删除旧恢复路径。

## 一步步怎么改

1. 接入 Ant Design 6 主题与 TanStack Query provider，建立 route/query key/request scope 基础。
2. 重写 App Shell、领域主导航、面包屑和 canonical route layout。
3. 把科目管理弹窗拆为科目列表与三个详情子路由；迁移资料和知识构建。
4. 把试卷详情设为主工作区，接入材料、作答任务和评分任务入口。
5. 把 PaperAnswering 收进试卷上下文的作答详情 Modal，并删除活动 job localStorage。
6. 把 Grading 拆成 route orchestrator、材料准备、Rubric 审核、逐题评分和整卷结果；阶段由事实派生。
7. 把 Reviews 改为队列 + 可审计详情，确认/改分后顺序推进。
8. 删除旧平级作答/评分入口、导航回调、全局请求科目、Radix 封装和无调用 CSS；旧 URL 只声明式重定向，不留兼容页面。
