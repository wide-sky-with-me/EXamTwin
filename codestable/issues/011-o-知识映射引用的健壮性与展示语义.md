# 知识映射引用的健壮性与展示语义

## 目标

逐题作答时，`knowledge_points` 的生成与展示保持“只接纳答案实际引用、且属于当前目录的
证据绑定编号”这一刚收紧的语义，同时把实现里两处隐式耦合和一处展示盲区显式化，避免
未来正则放宽或证据缺失时静默出错或前端展示与答案对不上。

## 范围

- 包含：`_cited_knowledge_codes` 的 citation 索引解析守卫；`_knowledge_references` 的
  `related` 证据来源取舍；`knowledge_points[i].references` 可能不含本次作答命中证据的
  展示语义记录。
- 不包含：改变知识映射的判定规则、恢复被移除的词面重叠回退、或调整拆题 Prompt 植入。

## 归属

- 独立 issue（不隶属现有 epic）。
- 相关 spec：`codestable/spec/index.md` “用证据回答问题”“整卷证据作答”边界。
- 关联：`codestable/issues/001-o-整卷证据作答与细粒度知识图谱.md` 中 2026-08-06 证据绑定
  知识点映射修复。

## 当前问题

`paper_answering.py` 的未提交改动把知识映射从词面重叠回退切到“答案引用驱动”，方向正确且
有测试。但实现里有三处健壮性 / 语义缺口：

1. `_cited_knowledge_codes`（`paper_answering.py:446`）对
   `citation_id.removeprefix("S")` 直接 `int()`，安全完全依赖
   `answering_agent/finalization.py` 的 `_CITATION_MARKER = re.compile(r"\[S([1-9][0-9]*)\]")`
   保证匹配一定是数字。正则一旦放宽，`int()` 抛 `ValueError` 会让整题失败，属隐式耦合。
2. `_knowledge_references`（`paper_answering.py:467-469`）的 `related` 只按
   `citation.knowledge_code == code` 匹配，不再用 token 重叠。正确，但若答案引用的那条
   citation 没带 `knowledge_code`，`related` 为空，`references` 就只剩库存预存片段，
   展示时可能与本次作答实际命中的证据“对不上”。这是有意的收紧，但取舍未记录。
3. `input_codes`（拆题兼容输入）仍作为 `Relevant knowledge` 注入提问，但最终
   `knowledge_points` 只展示被引用的证据，两者可能不一致；提示用但回显不用的差异未暴露。

## 影响范围

- 必须修改：`backend/src/examtwin/assessment/paper_answering.py`。
- 需要验证：`backend/tests/test_paper_answering.py` 中证据绑定映射相关用例。
- 仍待调查：无。

## 方案判断

以最小改动收口，不重定义语义：

- （1）`_cited_knowledge_codes` 的索引解析加 `isdigit()` / try-except 守卫，或复用
  `_CITATION_MARKER` 的解析结果直接携带索引，避免二次 `int()`。优先级最高，属防回归。
- （2）为 `_knowledge_references` 的 `related` 收紧行为补充注释，并在
  `codestable/spec` 或本 issue 记录“references 可能只含预存片段”这一展示取舍；
  不改变代码行为。
- （3）评估是否在 `PaperQuestionAnswer` 里暴露 `input_codes` 与最终 `codes` 的差异，
  或至少加注释说明注入提示与回显的语义不对称。若涉及 API 契约变更，先讨论再改。

## 实现设计

### 这次要怎么做

只做不改变判定规则的最小加固与语义记录。

### 一步步怎么改

1. 加固 `_cited_knowledge_codes` 的 citation 索引解析（守卫非法数字）。
2. 为 `_knowledge_references` 的 `related` 匹配与 `references` 展示写清注释。
3. 记录 `input_codes` 注入与最终 `codes` 的差异语义（代码注释级，暂不改契约）。

### 怎么确认做对

- 断言 `[S2]` 等正常引用仍按首次出现顺序去重映射且最多四个。
- 断言非法 citation 标记不再抛异常并整题失败。
- 断言 `knowledge_points[i].references` 在无命中证据时仍返回预存片段且不报错。

## 2026-08-13 检索结果去噪与答案引用闭合

- 真实经济学整卷中每题答案实际使用 1–4 条引用，但公开响应携带 15–37 条候选引用；原因是每次
  `knowledge_search` 把知识卡片的多条库存证据全部登记，运行时又把上下文内所有候选原样返回。
- 运行时现在先按答案中首次出现的 `[S#]` 选择真正使用的证据，再把标号压缩为连续序号并同步
  改写答案；题目引用列表与知识点映射因此共享同一组答案实际使用证据。
- `build_retrieval_cards` 不再把“题干与目录标题词面相似”单独当作公开知识点命中；知识卡片必须
  有真实召回节点的代码绑定或原文匹配。题干词面分数只作为已有证据的轻量排序先验。
- 每张知识卡片最多暴露两条去重后的强证据，工具侧再次执行同样上限，避免低价值库存片段挤占
  Agent 上下文。`018` 中 knowledge_point 节点的 `source_role` 索引缺口仍是独立未完成事项，
  本次没有把它冒充已修复。
- 验证：新增“纯词面匹配不生成卡片”和“只保留答案使用引用并重编号”回归；相关后端测试
  `81 passed`；历史结果读取也使用同一压缩契约。部署后再次读取真实 16 题任务，每题公开引用
  从原先 `15–37` 条收敛为 `1–4` 条，且每题引用数量与答案内去重后的 `[S#]` 数量完全一致。

## 2026-08-14 综合试卷跨单元知识映射修复

- 新任务 `ad623ed8-1082-450d-9c1b-b78ebcae2aaf` 的早期 trace 暴露了两层问题：组件为 U4 时，
  卡片目录硬过滤会拒绝跨单元节点；同时旧 evidence 注解自身也会错配，例如 Q3 被标成
  `3.2.2.3.O04`（储蓄的决定因素），Q14 被标成 `3.2.3.3.O04`，它们不能作为
  “已正确召回”的证据。这促使继续修复 `018` 的直接 knowledge_point 节点通道，
  而不是继续信任旧的原文块自动标注。
- 资料向量召回仍保留当前 Subject/Unit/来源/权威等级范围；只有已经被真实召回证据元数据
  明确关联的知识代码，在知识卡片映射阶段允许解析到同一科目的其他单元。这兼容综合试卷，
  同时不恢复“纯题干词面命中即可公开”的旧行为。
- 新增跨单元显式证据映射回归；知识映射、视觉门禁与分题契约合计 `65 passed`。
