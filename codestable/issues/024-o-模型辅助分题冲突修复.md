# 模型辅助分题冲突修复

## 目标

重叠分批为同一题产生冲突候选时，先让结构化模型在可信页级视觉主源中选择权威候选并重组题号；然后仍以
题号、子问、分值、来源页和视觉依赖的确定性守恒门禁验收。模型不能自由改写原题，无法闭合时继续失败关闭。

## 归属

- 隶属 Epic：`codestable/epics/002-o-科目与考试工作流重构/spec.md`
- 相关 spec：`codestable/spec/index.md`
- 延续已关闭来源完整性契约，不重新打开或改写历史 issue。

## 当前证据

- 预期行为：跨分批题目可从原页证明完整时继续作答；无法证明时给出可审计错误。
- 实际行为：最近任务 `6bdd4e10-368d-4dc9-a9a2-bc9bcec4dbf3` 完成 24/24 页视觉复核和 6/6 分题调用，但 Q9/Q10 的重叠候选在模型修复前被合并器拒绝。
- 最小场景：相邻主源分批都返回同一顶层题号，子问结构相同，但一份数学文本有 OCR/转写差异。
- 原始证据：Worker 于 2026-08-11 09:31:49 在 `splitting` 阶段保存 `ValueError: 同题号主源题干冲突，不能按文本长度择优`。

## 现状如何工作

原页先经多模态模型逐页复核并保存物理页标记，随后按字符与页段重叠分批拆题。当 `_merge_split_questions`
内部出现同题号文本冲突时，异常发生在 `_repair_question_structure` 之前，现有结构化模型修复通道无法接管。

## 影响范围

- 必须修改：`paper_answering.py` 的候选合并与结构化修复契约；分题 checkpoint 契约版本。
- 需要验证：实际 Q9/Q10 冲突、跨分批部分题、模型越界题号/候选索引、最终子问和分值不守恒、checkpoint 重试。
- 不改：Answering Agent、RAG、Mark Scheme 严格配对、历史答案与人工评分权威边界。

## 质量目标

- 功能正确性：
  - 目标：只有可信主源能逐项证明的题目才进入作答；重叠候选冲突不再阻止可证明的完整题。
  - 来源：用户决定与 project spec。
  - 预期证据：实际失败 checkpoint 回放及结构不守恒反例。
- 可靠性：
  - 目标：修复模型失败、越界、重复或选错候选时不产生部分题目，仍以原错误和修复错误失败关闭。
  - 来源：本次失败代价扫描。
  - 预期证据：结构化模型输出门禁测试。
- 性能效率：
  - 目标：正常无冲突试卷不增加模型调用；只有合并或页结构冲突时调用一次有界修复。
  - 来源：已有性能约束与本次风险扫描。
  - 预期证据：模型调用次数测试。
- 可维护性 / 可测试性：
  - 目标：候选分组、模型选择与确定性验收继续通过现有 `StructuredModelPort` 和单一分题入口验证。
  - 来源：现有模块边界。
  - 预期证据：最小服务行为测试，不 mock 确定性对账。

## 根因定位

- 根因链：物理页重叠分批 → 同题号多份主源候选 → 文本转写差异 → 合并器先于模型修复抛错。
- 证据：6 个持久 checkpoint 中 Q9/Q10 各有两份主源候选；单独回放合并器稳定复现相同 ValueError。
- 影响面：题目恰好位于重叠批次，且两次模型转写不完全包含时。

## 修复方案

1. 分题阶段先保留带来源身份的原始候选，把合并冲突交给现有结构化模型修复通道。
2. 修复输出对每个顶层题号必须指定一个权威候选索引；索引必须属于该组且题号同族。
3. 用选中候选作为结构锚点，只允许其他候选补足缺失标签/要求；冲突字段不再自动择长。
4. 用视觉复核主源的题号、子问、分值和来源页覆盖模型候选文本并做最终守恒验收。
5. 升级 checkpoint 契约；旧候选只能在新契约和输入摘要一致时复用。
