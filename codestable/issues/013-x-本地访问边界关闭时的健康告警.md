# 本地访问边界关闭时的健康告警

## 目标

单用户部署默认只允许 loopback 访问。当运维者关闭 `local_access_only` 且 API 暴露到
非 loopback 时，健康检查应把该配置状态标记为 degraded，提示当前没有认证兜底，防止
误配置导致接口裸奔。

## 范围

- 包含：在健康检查中把 `local_access_only=False` 且实际暴露非 loopback 标为 degraded；
  相关文档提示。
- 不包含：实现统一认证 / 授权 / tenant 绑定（README 已声明为多用户部署前提，不在本次）。

## 归属

- 独立 issue（不隶属现有 epic）。
- 相关 spec：`codestable/spec/index.md` “当前边界”与“运维入口”能力边界。

## 背景与证据

- `backend/src/examtwin/app/api/local_only.py` 的 `LocalOnlyMiddleware` 是 fail-closed：
  非 loopback 客户端一律 403 / 4403。这本身安全。
- `backend/src/examtwin/app/composition.py` 与 `app/main.py` 在 `local_access_only=False`
  时关闭该中间件后，**没有任何认证兜底**，所有 API 裸奔。
- README 明确“不要关闭后直接暴露到 LAN 或公网”，但当前健康检查（`healthcheck.py` /
  `app/api/healthcheck.py`）没有把这一误配置暴露出来。

## 操作方案

- 在健康检查读入当前服务绑定与 `local_access_only`：当 `local_access_only=False` 且服务
  监听或可见于非 loopback 地址时，健康状态标记为 degraded，并给出明确告警文案。
- 保持 loopback-only 且 `local_access_only=True` 的默认情形为 healthy。
- 涉及共享/部署状态判断，改动前需确认服务如何感知“暴露到非 loopback”（监听地址、
  环境变量或显式配置）。

## 风险边界

- 可能影响：健康检查返回值与 Compose `healthy` 判定。
- 明确不碰：不新增认证机制；不改变默认安全策略。
- 需要用户确认：非 loopback 暴露的判定来源（监听 host / 环境标识 / 显式开关）。

## 验证

- 单元测试：`local_access_only=False` 且非 loopback 标志 → 健康状态 degraded；
  默认 loopback + `True` → healthy。
- 既有：`backend/tests/test_health.py`、`test_observability.py` 相关用例。

## 关闭回写

- project spec：`codestable/spec/index.md` “运维入口”能力边界，补充“本地访问边界关闭且
  暴露非 loopback 时健康检查标 degraded”这一运维约束。

## 执行记录

- 新增显式 `API_BIND_HOST` 配置作为监听地址的单一权威信号；Compose 的 uvicorn 命令和应用
  Settings 读取同一值，默认仍为 `127.0.0.1`。
- 健康接口只在 `LOCAL_ACCESS_ONLY=false` 且 `API_BIND_HOST` 为非 loopback 时返回
  `degraded`，并给出“当前没有认证边界”的 warning；关闭中间件但继续绑定 loopback 不误报。
- 测试覆盖 `false + loopback`、`false + non-loopback`、`true + loopback` 三种组合；相关
  健康和契约专项回归纳入本轮 `44 passed`。

## 关闭结论

- 误配置现在可由健康状态直接观察，容器 healthcheck 会拒绝不受保护的非 loopback 暴露；
  默认本机部署行为不变。
- README、`.env.example`、Compose 和 Project Spec 已同步同一配置与告警语义。
- 本事项不实现认证、授权或租户；任何 LAN / 公网部署仍须先建立独立身份与权限边界。
