# 终稿降级引用与正态上尾计算收口

## 目标

最近一次 9660 S2 整卷作答的第一题必须能在结构化终稿服务失败时安全完成兼容恢复；兼容结果的引用仍只能来自正文实际使用且已检索的 `[S#]`。概率工具必须能直接计算正态分布上尾，避免模型把下尾结果误作题目要求的上尾概率。

## 范围

- 包含：兼容 JSON 中冗余 `citation_ids` 的正文派生；终稿整理失败类型的安全步骤摘要；`normal_sf` 概率运算及行为回归。
- 不包含：自动生成缺失的 Mark Scheme、保存模型草稿或隐式思维链、重写整套 ReAct 协议。

## 当前证据

- 任务 `9baafb32-205b-47b9-b56f-f4784fe7377d` 第一题连续三次失败，`answer_json` 为空；错误均为 `citation_ids` 与正文 citation 首次出现顺序不一致。
- 三次尝试都先出现“结构化答案整理不可用，正在使用兼容恢复”，但步骤未记录安全的异常类型。
- 第一次尝试为题目 `P(X>115)` 调用 `normal_cdf`，工具只返回 `P(X<=115)=0.0854517601`；正确上尾为 `0.9145482399`。当前概率工具没有 `normal_sf`，尽管描述声明 SF 表示上尾。
- 同场次 `9660:2026:JUN:S2` 有 Question Paper 但没有 Mark Scheme，无法以官方评分方案核验答案。

## 根因定位

1. 兼容 JSON 只在 `citation_ids` 为空时从正文派生；非空但过期、乱序或错误的冗余列表会让安全正文也被整体拒绝。
2. 终稿整理器异常被统一吞并为通用降级步骤，安全运行账本无法区分超时、契约错误和供应商错误。
3. 概率输入契约为二项和泊松提供 SF，却只为正态分布提供 CDF、区间和分位数；模型只能自行取补集。

## 质量目标

- 正确性：正文 citation 是兼容结果的唯一引用声明来源，仍由 allowed citation 集合拒绝伪造编号；正态上尾由确定性工具直接计算。
- 可分析性：只记录异常类型，不记录异常正文、模型草稿或隐式推理。
- 可测试性：从真实 ReAct 兼容恢复公开接口锁定引用行为，并用概率工具公开接口锁定上尾数值。

## 执行记录

- 兼容 ReAct JSON 现在始终从公开 `answer_markdown` 的 `[S#]` 首次出现顺序派生
  `citation_ids`，不再信任模型返回的冗余列表。运行时随后仍用 allowed citation 集合拒绝正文
  中未检索的编号；结构化终稿的严格引用校验保持不变。
- 终稿整理降级步骤增加异常类型，例如 `RuntimeError`、`TimeoutError` 或 `ValueError`；不写入
  异常正文、模型草稿或隐式推理。
- 概率工具新增 `normal_sf`，用 `erfc` 直接、稳定地计算 `P(X > value)`，并在工具 schema 和
  observation 中显式表达上尾事件。

## 验证

- TDD 红灯：真实 ReAct 兼容恢复接口在正文为 `[S1]`、冗余列表为 `S2` 时复现原
  `citation_ids must exactly match` 异常；修复后相同测试通过，伪造正文引用仍由既有 allowed
  citation 契约拒绝。
- TDD 红灯：终稿提供器抛 `RuntimeError` 时，旧步骤只有通用“兼容恢复”；修复后步骤包含安全的
  `RuntimeError` 类型且答案正常降级完成。
- TDD 红灯：`normal_sf` 原先被 Pydantic operation 契约拒绝；修复后公开工具接口返回
  `event=P(X > 115.0)` 和 `result=0.914548239884601`。
- 第一题确定性重放：`(a)(i)=0`；`(a)(ii)=0.914548239884601`，四位有效数字 `0.9145`；
  `(b)=123.624775209747`，四位有效数字 `123.6`。
- 答题链路定向回归：`101 passed`。后端完整非集成回归：`262 passed, 23 deselected`；Ruff
  check、format check、basedpyright 全部通过。唯一 warning 为本地 Qdrant payload index 的
  既有提示。
- 未自动重试原任务，避免未经授权的付费模型调用。

- 经用户授权后，以当前工作区重建 `examtwin-python:local`，并替换 API、2 个
  paper-worker 和 storage-gc 容器；部署前运行中试卷任务数为 0。重建后 API health contract
  为 `2026-08-05.evidence-difficulty-v25`，全部目标容器保持运行，API 为 healthy，两个 Worker
  均记录 `paper worker started`。`/api/v1/subjects/status` 显示 PostgreSQL、Qdrant、对象存储
  均可用，9660/9640 answering 均启用。Worker 容器内重放兼容终稿引用恢复，将正文 `[S1]`、
  冗余列表 `S2` 规范化为 `["S1"]`；重放 `normal_sf` 得到
  `P(X > 115.0)=0.914548239884601`。
