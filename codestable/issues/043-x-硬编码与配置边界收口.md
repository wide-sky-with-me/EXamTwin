# 硬编码与配置边界收口

## 目标

消除会让 API 地址、供应商、模型预算、解析策略、业务阈值、科目扩展和主题表现发生隐性分叉的硬编码；稳定协议常量保留为具名契约，部署或供应商能力改为配置，科目差异归属 Subject Package，视觉值归属主题 token。

## 范围

- 统一 API 前缀、公开资源 URL 和 API 端口的单一权威来源。
- 把 LLM、Embedding 和 Rerank 的供应商配置及适配器命名收口到 provider-neutral 边界。
- 配置化模型输入预算、最终化超时和知识库 MinerU 超时/重试。
- 集中难度分档、评分置信度和成绩建议阈值。
- 将内置科目的图标、颜色和架构门禁改为 Subject Package 数据驱动。
- 收口前端直接颜色与重复分页配置，保持毛玻璃主题和深浅色一致。
- 修正 Project Spec 中已经失效的模型分支描述。

不包含：更换当前检索供应商、重做视觉设计、调整现有业务阈值数值、修改 API v1 路由形状或执行数据库业务数据迁移。

## 当前问题

- `API_PREFIX` 可配置，但前端资源归一化、Worker 图片 URL 和答案图片 URL 固定为 `/api/v1`；API 端口也在 Compose、CLI 和健康检查重复。
- LLM 已统一经 LiteLLM，但配置默认值仍绑定具体供应商；Embedding/Rerank 的命名、错误恢复和 endpoint 仍直接绑定 SiliconFlow。
- 评分、Rubric、视觉和最终化的输入长度/超时分散在业务代码；知识库 MinerU 固定超时 1200 秒、重试三次。
- 难度 `0.34/0.67` 被重复实现；评分置信度和成绩建议阈值没有具名政策边界。
- 内置科目展示信息和架构门禁维护两份科目清单；Compose 默认语料根指向数学。
- 前端样式存在大量绕过主题变量的直接颜色，分页大小也在页面重复声明。
- Project Spec 仍描述按 `gpt-5.6` 模型名决定请求参数。

## 行为保持

- API 继续使用 `/api/v1`，当前端点和 OpenAPI 路径不变。
- 当前 DMXAPI、SiliconFlow、数学 9660、经济 9640、模型选择、超时/阈值数值和分页默认行为不变。
- 不改变数据库已有 ID、对象键、公开资源 URL 或 Subject Package digest 的审计语义；若 manifest 纳入展示元数据，必须显式接受并测试 digest 更新。
- `.env` 中现有凭据只迁移变量名或读取路径，不打印、不提交。

## 实施顺序

1. API 契约和端口单一来源。
2. 供应商配置与适配器边界。
3. 模型预算、最终化和 MinerU 策略配置。
4. 业务阈值集中。
5. Subject Package 驱动展示和架构门禁。
6. 主题 token 与分页配置收口。
7. 文档同步、全量验证、运行态核验和独立 review。
