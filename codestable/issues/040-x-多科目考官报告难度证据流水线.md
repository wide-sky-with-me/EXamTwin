# 多科目考官报告难度证据流水线

## 目标

在 Issue 039 的课程运行边界上，用同一条通用流程把数学 9660 与经济 9640 的 Examiner Report 转换为可核查的 A/B 级题目难度候选，经确定性验证和人工审核后幂等发布；新增科目不得修改流水线主流程。

## 范围

- 包含：来源生命周期对账；构建 run、候选、追加式审核与正式投影；通用结构化抽取；逐字引用、页码、pair_key、题号和科目校验；审核 API/UI；双科真实发布；合成第三科契约测试。
- 不包含：一次处理全部报告；抽取阶段自动映射 knowledge_codes；新增第三个真实科目；把 B 级定性描述强制换算成伪精确数值。

## 归属

- 隶属 Epic：`codestable/epics/001-o-多科目知识生产与难度证据流水线/spec.md`
- 前置：`codestable/issues/039-x-课程扩展主流程去硬编码.md`

## 背景与证据

- 两科当前共有 37 份 Examiner Report 目录记录，但 `question_difficulty` 为 0，且报告当前均为 archived/deleted 状态。
- `assessment/examiner_evidence.py` 无生产调用方，包含数学 TOPIC_KEYWORDS、UNIT_CODES、Markdown 标题正则和固定难度常数，并直接 upsert 正式数据。
- 当前 Project/Vision 明确禁止把 D 级冷启动表述为真实表现校准。

## 质量目标

- 功能正确性：正式观测全部严格闭合到科目、来源、场次、Unit、题号、原文和页码。
- 可核查性：输入哈希、来源校验和、块哈希、模型与提示词版本冻结；每行可回读逐字原文。
- 可靠性：歧义、缺页、错科、错场次和失败运行不发布；旧正式版本保持可用。
- 可维护性/灵活性：主流程无科目关键词和代码分支；第三科只提供 Package/样本。

## 实现设计

1. 各选一份 9660/9640 报告与严格配对 QP，先证明结构块、页码和规范题号能闭合。
2. 新增 difficulty evidence runs/candidates/reviews，`question_difficulty` 只保存已审核正式投影。
3. 模型只返回类型化原始候选；代码验证逐字引用、身份、题号与数值范围。
4. A 级保存明确官方量化指标；B 级保存官方定性原文，不在抽取阶段赋固定常数。
5. 审核后以 run 为版本事务发布；重复输入复用且不增殖。
6. Subject Knowledge 工作区提供候选查看、接受/拒绝/修改和显式发布。
7. 双科各发布一组非零正式数据；再单独设计题目到知识点的审核映射与聚合。

## 风险与穿刺

- 首要风险：归档报告是否仍有稳定对象、Markdown、页码和严格配对身份；若不成立，先修来源生命周期，不写正式表。
- 次要风险：报告题号与 QP 规范题号不一致；不以正则猜测，歧义进入人工审核。

## 验证

- 两科正式 A/B 行非零；全部可回读原文与页码。
- 重复运行不增殖；错科、错场次、无效题号、引用不实不得发布。
- 发布失败保持旧版本；模型不可用只令 run 失败。
- 合成第三科通过同一接口，主流程无已知科目代码。
