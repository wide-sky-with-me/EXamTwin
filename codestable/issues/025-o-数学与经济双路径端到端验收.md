# 数学与经济双路径端到端验收

## 目标

在真实浏览器和当前持久服务上，分别为数学 9660、经济 9640 跑通两种答卷来源：系统 AI
作答记录与外部上传答案。每条路径都继续完成严格配对的官方 Mark Scheme 上传/选择、解析、
评分细目审核确认、逐题 AI 自动评分和整卷报告；发现阻断即修复并从原失败步骤复验。

## 范围

- 包含：双科作答、外部答案导入、官方 Mark Scheme、评分标准审核、逐题 AI 评分、整卷报告、
  复核队列可见性、浏览器交互和相关自动化回归。
- 包含：验证已准备的经济 9640 合成外部答案 fixture；它只用于工作流验收，不冒充真实学生答案。
- 不包含：正式成绩发布、学生账号/班级统计、扫描答题卡 OCR、使用邻近场次 Mark Scheme
  替代缺失配对材料、自动确认最终人工成绩。

| 数学 9660 | 上传答案 | 2019 JAN P1 合成答案 fixture | 10 题导入 → 同一官方 MS → 细目确认 → 10/10 AI 评分 → 整卷报告 |

每行还必须确认：科目标识、Unit、年份/考季与 `pair_key` 一致；报告只读取当前 rubric
版本的 assessment；评分结果进入对应科目的复核队列，不跨科污染。

## 质量目标

- 功能适宜性：四个矩阵场景全部达到整卷报告，任一单科成功不能代替另一科。
  - 证据：浏览器运行日志、任务/评分 API 快照与结果截图。
- 可靠性：长任务可观察、失败可从所属阶段重试；页面不得无限等待或只显示泛化错误。
  - 证据：轮询状态、worker 日志和原失败路径复验。
- 信息安全性与数据完整性：服务端继续校验科目归属和严格 QP/MS 配对；不得用邻近卷兜底，
  不得覆盖历史人工审核与最终分。
  - 证据：四行材料身份对账、跨科负例和当前 rubric/assessment 关联检查。
- 交互能力：四步评分流程在浏览器中可完成；弹窗、上传、审核、错误提示和报告入口可见可操作。
  - 证据：Playwright 真实浏览器检查，不仅验证 API。
- 可维护性/可测试性：两种答卷来源在导入完成后复用同一评分接口与浏览器流程；自动化脚本参数化
  科目与材料，不复制四套脆弱脚本。
  - 证据：专项测试、全量测试、前端测试/构建/lint 与参数化 E2E。

## 风险与穿刺

按“不确定性 × 失败代价”排序：

1. **经济系统作答是否能完成**：先上传 2024 JAN U1 QP，证明分类、视觉复核、分题与经济
   Agent 作答闭合；不通先修该主路径，不提前做经济评分 UI 打磨。
2. **双科严格配对是否闭合**：分别上传精确配对 MS，核对解析身份；任何年份/考季/Unit
   不一致均失败关闭。
3. **外部答案导入是否复用评分主路径**：数学 fixture 先穿刺；再验证已准备的
   经济 fixture，确认 `answer_mode=uploaded` 且题号集合与 QP 闭合。
4. **评分与报告是否可完成**：每科先选一条路径完成 rubric 审核与单题评分，再扩展到全题、
   第二入口和整卷报告。
5. **跨科隔离**：数学 ID 带经济上下文、经济 ID 带数学上下文均应拒绝或不可见。
