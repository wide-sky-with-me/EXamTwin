# 科目与考试工作流重构

## 这个 Epic 要改变什么

把当前以“状态总览 + 全局科目上下文 + 独立知识库”为中心的工作台，重构为领域对象优先的四个稳定入口：科目、试卷库、任务和复核；任务内再区分作答与评分。科目和试卷保存事实，任务承载运行，复核完成最终人工决策。前后端共同支持科目 CRUD、试卷资料归档与严格配对、外部答案材料、AI Mark Scheme 草案和跨科目复核；保留现有数学 9660、经济 9640 的全部持久数据，不重建数据库、知识库或向量索引。

## 为什么现在做

当前界面把基础设施健康、领域约束、资料统计和用户任务同时暴露，状态总览、左下科目上下文、独立知识库和流程页面之间层级重复。已有后端能力足以支撑资料、知识、作答和评分，但入口按技术边界组织，导致功能杂乱、主要任务不连续。需要在不损失既有能力与数据的前提下，按教师的实际工作流重切产品和应用边界。

## 关联 Project Spec

- `codestable/spec/index.md`：本 Epic 将改变当前“状态总览 / 独立知识库 / 全局科目上下文 / 只接收系统作答记录和官方 Mark Scheme”的 Web 使用路径；关闭后把已验证的新路径合并回当前真相。
- `codestable/epics/001-o-多科目知识生产与难度证据流水线/spec.md`：继承科目隔离、受控知识版本、证据化作答、人工确认评分和审计边界；用户最新决定覆盖其中关于状态总览与独立知识库入口的旧 UI 方案。

## 当前方案

### 稳定导航与生命周期

```text
ExamTwin
├─ 科目
├─ 试卷库
├─ 任务
│  ├─ 作答任务
│  └─ 评分任务
└─ 复核
```

移除状态总览、独立知识库入口、左下角科目上下文切换、品牌副标题、基础设施状态卡、资料构成、上下文隔离和自动评分说明等非任务信息。试卷详情是材料、作答和评分的共同上文；作答与评分入口只做跨科目任务队列，不再要求用户重复选择已经由 URL 确定的科目、试卷和任务。后端科目隔离继续保留，客户端选择不能替代服务端归属校验。

### 科目

科目索引展示预设图标、固定主题色、名称、代码、资料数、知识点数、向量数和业务状态。新增科目使用受控弹窗或抽屉；管理已有科目进入稳定详情 URL，不再在宽幅管理弹窗中模拟完整页面。

科目详情只保留三个业务子路由：

```text
基本信息 | 资料 | 知识库
```

基本信息只允许修改名称、图标和颜色；科目标识、科目代码、课程体系与能力模板只读。资料页支持查看、上传、替换和删除。知识库页只保留核心/补充知识库版本、输入资料、重新构建和发布状态；现有图谱生产与层级浏览 UI 从产品界面移除，不删除已持久化图谱及后端作答能力。

所有科目均允许物理删除。删除数据库业务数据、对象存储内容和科目专属 Qdrant 集合/别名；运行中任务存在时拒绝删除。内置 SubjectPack 不再随启动自动重建被删除科目，而作为新增科目时可重新使用的能力模板保留。

### 试卷库

页面支持跨科目进入，科目是可持久化到 URL 的筛选条件，不是展开试卷前的卡片门禁。科目内按试卷单元归档 Question Paper，支持添加、修改显示名称、受控删除、分页、名称/文件名搜索，以及年份、考季和 Unit 分类筛选。试卷详情直接显示全部 Question Paper、同一严格 `pair_key` 下的 Mark Scheme、Source Booklet、作答任务和评分任务；从详情发起作答或评分时沿用当前上文。只有科目、年份、考季和 Unit 全部一致的材料显示为已绑定，身份缺失或不一致时明确阻止或提示，不提供绕过严格配对的手工覆盖。

### 作答任务

任务入口默认展示可筛选、查看、单条或批量删除的跨科目作答队列；详情由带 `subjectId`、`paperUnitId` 和 `jobId` 的 URL 唯一确定。活动任务不再用 `localStorage` 充当导航事实。

从试卷详情新建作答时，科目和试卷已经确定，只选择具体 Question Paper、可选 Source Booklet 与知识版本；独立上传仍允许先选择科目再上传材料。详情保留持久 Worker、实时进度、逐题答案、引用、图表、来源页和失败重试。只渲染当前事实对应的状态，不用空面板提前占位。

### 评分任务

评分入口是跨科目任务队列；详情必须包含明确作答 `jobId`，不能只凭试卷单元隐式选择第一条记录。页面阶段由材料、Rubric、assessment 和复核状态派生，不保存可与后端事实漂移的独立步骤：

```mermaid
flowchart LR
  G1[材料缺失] --> G2[准备或生成评分规则]
  G2 --> G3[审核评分规则]
  G3 --> G4[AI 逐题评分]
  G4 --> G5[整卷结果]
  G5 --> G6[等待复核或已终稿]
```

材料路径：

1. 系统作答记录：从试卷详情或任务队列进入，自动取得科目、试卷和答案；严格匹配的 Mark Scheme 自动成为候选，存在多个候选时显式选择。
2. 自行上传：支持试卷与答案分别上传，也支持一个包含题目和答案的合并 PDF / Markdown；解析后先展示题号映射，确认后继续。本 Epic 不支持扫描手写答题卡 OCR。

有官方 Mark Scheme 时继续使用受控上传和审核。没有官方版本时，只有当前科目已经发布课程大纲和核心知识库，才能让 AI 根据课程大纲、知识库和试卷生成标为 `ai_generated` 的评分规则草案；缺少前置资料时阻止生成并引导到科目详情。草案保存模型、提示词版本、来源知识版本和生成时间，教师逐条审核、修改并确认后才能评分，不冒充官方 Mark Scheme。

整卷结果继续使用持久化逐题 assessment 聚合总分、完成度、共性问题、整体建议和逐题建议。AI 结果仍是建议，最终确认进入复核。

### 复核

复核入口默认合并展示全部科目的待复核项，每条显示科目并支持按科目和置信度筛选。提交决定前必须展示题目、答案、Rubric 原子、逐项得分、证据/警告、建议总分和置信度；不能只凭队列摘要确认或改分。人工确认、改分、最终分范围和审计记录规则不变。

## 界面与交互变化

### 目标界面

- 角色与入口：教师通过固定侧栏进入科目、试卷库、任务和复核四个领域入口；移动端任务内切换作答/评分。
- 图示状态：目标。

```text
┌─ 深墨蓝侧栏 216px ─┬─ 冷灰页面 / 白色业务表面 ───────────────────┐
│ ExamTwin           │ 试卷库 / 9660 / 2025 June P2              │
│   科目              │ Question Paper · Mark Scheme · Booklet    │
│ ● 试卷库            │ [新建作答] [选择已完成作答并开始评分]       │
│   任务              │ 作答任务 3 · 评分任务 1                    │
│   复核  5           │                                            │
└────────────────────┴───────────────────────────────────────────┘
```

- 默认浅色“明亮学院管理台”：页面背景 `#F4F6F8`、内容表面 `#FFFFFF`、主文字 `#18202B`、侧栏 `#17212B`、主操作 `#2F6FED`、成功状态 `#16846A`。
- 科目以预设图标、固定主题色和资料夹索引色条识别；详情沿用其主题色。
- 页面标题 28–32px；控件 38–44px；卡片圆角 12–14px；弹窗圆角 16px。卡片靠边框分层，阴影仅用于弹窗、菜单和浮层。
- 创建动作可使用 Modal/Drawer；已有科目、试卷、任务和复核详情使用稳定页面。移动端详情全屏，不把桌面表格压进窄屏。
- 不使用渐变大背景、玻璃拟态、纯装饰指标卡、大量胶囊标签或宣传文案。
- 保留浅色、深色和跟随系统，但三种模式共享同一信息结构。
- 统一使用 Ant Design 6 承载主题、表单、表格/列表、上传、弹窗、抽屉、分页、反馈和可访问性；Lucide 保留为图标体系。页面优先使用 design token 和组件语义插槽，不覆盖 Ant Design 内部 DOM。
- TanStack Query 只拥有服务端状态、请求取消、精确失效和 SSE 快照缓存；React Router 拥有业务 URL，Ant Design Form 拥有表单草稿，局部组件只拥有瞬时展示状态。

## 架构考量

- 前端壳只拥有导航、主题和全科目目录；`subjectId`、`paperUnitId`、`jobId`、`assessmentId`、筛选和页码属于 URL。每次科目请求显式携带请求上下文，不再由页面调用全局 mutable `setApiSubject`；query key 必须包含科目和业务身份，旧科目请求取消或晚返回时不能覆盖当前流程。
- `subjects` 继续拥有科目生命周期、能力模板和资料归属；新增更新/删除应用服务隐藏数据库、对象存储和 Qdrant 清理顺序。
- `knowledge` 继续拥有资料注册和知识版本构建；移除 UI 不等于删除后端图谱事实或作答检索能力。
- `assessment` 增加可评分提交（系统记录、分离文件、合并文件）和 AI 评分规则来源，统一映射为现有逐题评分输入，避免在评分服务内堆三套分支。
- FastAPI 只处理协议、上传流和错误映射；OpenAPI 是前后端契约单一来源。
- 数据库只做向前兼容 Alembic 迁移，不 drop/recreate、不重跑 inventory、不重建知识库或 Qdrant alias。

## 质量约束与取舍

- 功能适宜性：数学 9660 与经济 9640 必须分别完成科目管理、试卷管理、作答、评分和复核；一科成功不能代替双科成功。
- 交互能力：每页只有一个主要任务；危险删除明确范围并二次确认；加载、空、失败、禁用和长任务进度就近显示；宽幅弹窗具备焦点约束和键盘关闭规则。
- 可靠性：迁移后现有两科的资料、知识版本、向量别名、作答、Rubric、assessment 与复核保持可读；失败清理不能留下半删科目或半写提交。
- 信息安全性：所有科目相关读写继续在服务端校验科目归属；流程内选择只改变客户端请求上下文，不成为授权替代品。
- 可维护性：科目生命周期、提交解析、Mark Scheme 来源与 UI 流程状态各有单一所有者；删除旧导航、旧状态面板和旧调用路径，不留兼容 UI。
