# 2026-08-03 启动种子清空正式定义证据

## 现象

运行态审计发现正式环境 `definition_evidence` 为 0；183 个学习目标只有置信度 0.3 的 D 级冷启动难度；
chunk 到知识点的词面匹配出现单点 817 条证据的热点失真。

## 根因链

1. API 启动时执行知识种子，先删除定义证据再从课纲重建。
2. 容器内按宿主机绝对路径定位 Markdown 缓存，syllabus 读取失败，抽取结果为空。
3. 删除不以“新数据可用”为前提，空抽取直接覆盖了正式数据。

## 修复

- 统一可移植的 Markdown 缓存定位：宿主绝对路径在容器内按稳定文档 ID 映射到挂载缓存。
- API 启动只执行 schema 迁移和无破坏兼容检查，不建图、不调用模型。
- 知识构建改为显式 `knowledge-build` run：来源不可读、抽取为空、结构不完整时失败关闭，正式图谱在
  单事务内发布。重新发布后 `definition_evidence` 恢复为 183。

## 教训

破坏性写入必须在新结果完整可用之后进行；正式数据只通过显式、可审计、可失败关闭的发布入口替换。
