# 2026-10-03 清理 Docker 资源时删除了被保留的旧数据卷

## 现象

一次“删除垃圾容器”的清理中，Agent 把四个未挂载的卷 `examtwin_postgres-data`（约 63 MB）、
`examtwin_qdrant-data`（约 2.2 MB）、`examtwin_seaweedfs-data`（约 4.9 MB）、`examtwin_temporal-data`
描述为“旧版本遗留数据”，经用户勾选后执行了 `docker volume rm`，删除不可恢复。

2026-09-08 恢复本地开发基线时，这几个旧卷被明确记录为“保持不动”。当前 Compose 使用的是
`examtwin_examtwin_*` 命名卷，开发库为当日新建空库，原始资料尚未重新入库。

## 影响评估

- Qdrant 与 SeaweedFS 卷的体量不足以容纳 2026-09-01 运行态的数万个向量点和转换产物，删除的不是该
  运行态的索引与对象。
- 63 MB PostgreSQL 卷的具体内容无法再确认。
- 工作区内没有任何 Compose 文件引用这四个卷名。

## 根因

删除前只检查了“是否被容器挂载”和体积，没有检索项目记录中对这些卷的保留决定，就把“未挂载”等同于
“无用”，并在给用户的选项里使用了“旧版本遗留数据”的定性。

## 措施

- 删除卷、数据库或对象前，先检索 `docs/`、`.agents/notes/` 与 git 历史中对目标的记录；有保留记录时
  向用户说明该记录，再请求确认。
- 对未知内容的数据卷，先只读导出摘要（表清单、行数、对象数）再决定是否删除。
- 规则写入根目录 `AGENTS.md` 的约定。
