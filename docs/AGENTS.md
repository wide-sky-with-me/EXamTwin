# docs/ 规则

`docs/` 只描述当前系统怎样运转。为什么这样定、否定过什么写在 `.agents/notes/`，历史在 git。

## 结构：一事实一归宿

| 位置 | 内容 |
|---|---|
| `architecture.md` | 产品不变量、运行拓扑、模块地图、数据所有权、安全边界；只做导航，不展开细节 |
| `subsystems/` | 一个子系统一篇参考：行为、契约、门禁、配置项 |
| `cookbook/` | 操作手册：每步带编号和可执行的验证命令 |
| `postmortem/` | 真实事故与踩坑：现象、根因链、修复、教训；唯一允许叙述经过的目录 |

上层只放一行链接，细节下沉到专属文档。同一事实只在一处讲透，其余位置链接过去。

## 去废话守则

- 只写当前事实。禁止 `以前`、`现在`、`不再`、`改名为`、`曾经`、`原先`、`此前` 等变迁叙述（`postmortem/` 除外）。
- 不手抄能由代码、OpenAPI 或配置推导的清单（完整 API 列表、全部环境变量）；引用权威文件路径。
- 不写只有当时会话才懂的引用（“见上次讨论”“issue 12”）；引用仓库内可解析的路径。
- 命令和路径必须能在当前仓库执行或解析。

## 字数预算

`doc-budgets.json` 为每个文档设上限，单位是汉字数加英文词数。超限时依次：把细节下沉到子文档；删掉
套话并精简；仍需更多空间时在同一次改动中调整预算并在提交说明里写明理由。

## 校验

```bash
uv run python scripts/check_docs.py
```

检查预算、变迁用词和相对链接，CI 必跑。
