# 评分与复核

评分只能从具体试卷的具体作答记录进入。模型提出建议，教师拥有每一个状态迁移的最终决定。

## 材料门禁

- 作答任务必须已完成或部分完成。
- Mark Scheme 必须与作答所属试卷有完整且完全相等的科目、年份、考季与 Unit。身份不完整或不一致时
  阻止评分，没有手工覆盖。
- Mark Scheme 转换产物按来源校验和不可变保存；评分规则冻结来源文档与校验和，来源变化后旧规则不会
  被新内容静默复用。
- 没有官方 Mark Scheme 时，只有当前科目已发布 syllabus 与核心知识库，才可生成标为 `ai_generated`
  的评分规则草案；草案保存模型、提示词版本、知识版本和生成时间，不冒充官方版本。

## 评分原子

`POST /api/v1/grading/rubrics` 把 Mark Scheme 解析为版本化的 point-based / levels-based 原子，保留题号、
子问、分值类型（M/A/B/FT 等）、依赖、替代路径、精度、单位、FT 规则和来源摘录。每条原子初始为
`pending`。

- 单条审核：接受、拒绝或编辑后接受；必须填写审核人，前后内容写入不可变审计记录。
- 批量审核：对当前筛选下至多 200 条原子做混合决定，单事务全有或全无，每条仍独立审计。
- AI 审核：按题有界并发，只追加 `accept / reject / revise` 建议、置信度、理由和建议 patch，不改变
  人工状态；教师填写审核人并确认后，接受 / 拒绝建议才作为批量人工决定应用，`revise` 必须单条编辑。
- 所有原子都有人工记录且至少一条被接受，规则版本才能确认。

## 逐题初评

`POST /api/v1/grading/papers/{paper_job_id}/questions/{position}/assess` 只使用已确认版本中当前题的已接受
原子。模型结果必须与原子逐项对应，重复、遗漏或虚构原子拒绝保存；上限、说明与类型以服务器确认版本
为准。正分需要非空逐字证据，纠错后仍缺证据则暂缓该项授分。受限 CAS 只佐证符号等价。

矢量图结构随文字进入评分并保存；位图或依赖原卷底图的产物无法可靠检查时，整题以零置信度暂缓，提示
教师查看实际产物，占位零分不表示答错。策略主动留空的题按已确认原子确定性记零，仍需复核。

结果写入 assessment，状态必为 `pending_review`，保存逐原子建议分、证据、理由、置信度、错误类型、
改进建议和所用知识版本。

## 复核

`GET /api/v1/grading/reviews/all` 跨科目返回待复核项，携带 `paper_job_id`、试卷显示名、题位与
`answer_mode`。教师通过 `POST /api/v1/grading/reviews/{assessment_id}` 确认建议分（`confirmed`）或填写
最终分（`overridden`）。最终分必须在 `[0, total_available]`，由仓储事务内的领域校验强制。

## 整卷总览与单元等级

总览按指定评分规则选择每题最新 assessment，使用持久化最终分，明确列出缺失题，确定性聚合共性问题与
建议，不调用模型、不新增总分事实源。

单元等级用同一持久化总分查 `assessment/grade_boundaries.json` 中的官方分数线：科目、年份、考季、Unit、
评分规则身份和官方满分必须完全匹配。待复核得分只显示暂定等级；未评完、存在暂缓授分、缺少分数线或
身份错配时显示不可估计及原因。不从固定百分比推算，不输出单卷 A* 或资格等级。
