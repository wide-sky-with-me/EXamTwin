# Agent Note: 工作台以科目、试卷、复核三个领域对象为入口

Status: implemented

## Problem

工作台曾有五个平级入口（科目、试卷、作答、评分、复核），外加状态总览、全局科目下拉与独立知识库。
作答与评分其实是对试卷的运行，复核是对评分的人工决定；平级导航迫使每个页面重复选择科目、试卷和材料，
活动任务存在 `localStorage`，评分页保存可与后端事实漂移的步骤，复核时看不到题目和证据就能确认。

## Decision

- 主导航只有科目、试卷、复核；作答与评分在具体试卷与作答记录的 URL 上下文内展开。
- URL 拥有业务身份（科目、试卷单元、任务、assessment、筛选、页码）；TanStack Query 拥有服务端状态、
  请求取消与精确失效；Ant Design Form 拥有表单；局部组件只拥有瞬时展示状态。
- 每次请求显式携带科目上下文；query key 含科目与业务身份，切换时旧请求取消。
- 评分阶段由后端事实纯函数派生；`localStorage` 只保存用户偏好。
- 复核详情在提交前展示题目、答案、原子、逐项得分、证据与置信度。
- Ant Design 6 承担通用控件；自定义 CSS 只用于领域内容布局。
- 旧 URL 只做一次声明式重定向，不保留第二套页面实现。

## Implementation bounds

上述状态所有权条款是开发约束，不等同全库完成声明。导航和业务身份已落在路由；列表、筛选、草稿、任务
快照和评分步骤仍有局部状态，外部答案导入仍保存科目级任务 ID，Query 取消与 Form store 未全面覆盖。
当前实现归属见[前端工作台](../../../../docs/subsystems/frontend-workbench.md)，不把局部整理当作状态迁移。
复核分组规则的独立归属见[分组决定](../simplification/2026-10-14-review-queue-grouping.md)。

## Alternatives considered

- **保留五个平级模块** — 改动最小。重复发现上下文，错误配对风险高。
- **XState 管理评分阶段** — 状态机显式。阶段可由后端事实推导，额外运行时会成为第二事实源。
- **Ant Design ProComponents** — CRUD 页面更快。当前没有三个以上同构 CRUD 页面，暂不引入。
- **继续自研或 Radix 封装通用控件** — 视觉完全自控。维护成本高，可访问性与响应式要自行保证。

## Consequences

- **收益**：刷新、复制链接、前进后退都回到同一上下文；晚返回请求不会覆盖当前页面。
- **代价与已知上限**：页面深度增加，入口依赖试卷单元数据完整；界面不提供跨试卷的作答或评分总队列。
