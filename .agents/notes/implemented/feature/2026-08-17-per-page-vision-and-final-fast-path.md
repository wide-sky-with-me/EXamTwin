# Agent Note: 视觉复核保持一页一请求，靠削减重复输入与重复调用降延迟

Status: implemented

## Problem

整卷耗时主要在外部模型：实测解析约 17–20 秒，而视觉与分题阶段数学 332 秒、经济 1598 秒，同一固定卷
在 267–2073 秒之间波动。旧实现把整个 3–5 页分块的 Markdown 复制给每一页视觉请求（实测累计放大约 4.85
倍），视觉响应只靠提示词约束 JSON，且每道题即使主模型终稿已合法仍固定再调用一次结构化终稿模型。

## Decision

- 视觉复核保持一物理页一请求、原渲染清晰度和既有门禁；默认每 Worker 两路并发。
- MinerU `content_list` 按 `page_idx` 先生成页级 Markdown，视觉请求只携带当前页文本；未知块类型或缺失
  页码时回退原整块，不丢内容。
- 视觉请求使用 strict JSON Schema 与配置的推理强度。
- ReAct 主模型终稿先按 `AgentFinalPayload`、精确子题与允许引用集合本地验收；通过即直接成为终稿，失败
  才调用结构化终稿 provider。
- 视觉成功请求记录页码、attempt、耗时与页级文本长度。

## Alternatives considered

- **多页合并为一次视觉请求** — 请求数最少。会重新引入跨页视觉归属风险，用质量换速度。
- **提高视觉并发** — 简单直接。尾延迟本身来自供应商波动，未做双卷供应商基准前提高并发可能放大限流。
- **始终调用结构化终稿模型** — 输出格式最稳定。主模型已合法时第二次调用不是正确性前提。

## Consequences

- **收益**：输入重复与多余终稿调用被消除；格式性重试减少。
- **代价与已知上限**：外部逐页视觉推理仍是整卷主要耗时，输入收口不等于显著加速；并发上限仍待基准。
