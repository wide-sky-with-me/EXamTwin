# Agent Note: 评分的每个状态迁移都经人工门禁，AI 只追加建议

Status: implemented

## Problem

自动评分如果直接产出成绩，模型的抽取错误、虚构评分点或证据缺失会无声地变成最终分。评分还需要能
回到官方 Mark Scheme 的具体条目，并区分哪些判断来自人、哪些来自模型。

## Decision

- 评分只用与作答完全同场次的官方 Mark Scheme；转换产物按来源校验和不可变，评分规则冻结来源。没有官方
  版本时，AI 草案须标为 `ai_generated` 且要求已发布 syllabus 与核心知识库。
- Mark Scheme 解析为版本化评分原子，初始 `pending`；人工逐条或批量（单事务、全有或全无、逐条审计）
  决定后，且至少一条被接受，规则才能确认。
- AI 审核只追加 `accept / reject / revise` 建议，独立存表，不改变人工状态；教师确认后才作为人工批量
  决定应用，`revise` 必须单条编辑。
- 逐题初评只用已接受原子；模型结果须与原子逐项对应，重复、遗漏或虚构即拒绝；正分需要逐字证据，否则
  暂缓授分；无法可靠检查的位图使整题以零置信度暂缓。
- assessment 创建即 `pending_review`；只有教师确认或改分形成最终分，改分范围 `[0, total_available]`
  由仓储事务内校验强制，不依赖 HTTP 层。
- 整卷总览确定性聚合每题最新 assessment，不调用模型、不建总分表。

## Alternatives considered

- **模型直接给出最终分** — 最省教师时间。模型错误会直接成为成绩，且无法审计。
- **AI 审核结果直接更新原子状态** — 减少一次确认。AI 建议会被误当成人工决定，规则确认门禁失效。
- **总体建议再调用一次 LLM 总结并持久化报告实体** — 文字更自然。会新增第二个可漂移的总分与建议事实源；
  触发重访：需要教师编辑总评、跨次比较或正式报告发布。
- **AI 审核做成后台任务** — 规模大时不受 HTTP 超时限制。当前同步有界并发足够；触发重访：真实 rubric 规模
  或供应商延迟超过 HTTP 超时。
- **只在 HTTP 契约层校验改分下限** — 已有 `ge=0`。Worker 或 CLI 直接调用仓储时可写入负分。

## Consequences

- **收益**：任何模型输出都不能绕过人工形成最终分；每次决定都有审计。
- **代价与已知上限**：教师需要逐题复核；评分准确性只有小规模同源样例评测，不是教师双评金标准。
